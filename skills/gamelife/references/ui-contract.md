# GameLife HTML 工作台契约

## 目标

`assets/gamelife.html` 是可以直接在浏览器打开的真实交互界面，不是截图或静态演示。`assets/gamelife.js` 负责 UI 状态、浏览器本地保存和交互；它不依赖服务器、构建工具或第三方 CDN。

## 必须保留的区域

1. **Hero / 总进度**：深蓝到青绿色渐变、GameLife/Adventure Log 文案、任务总数、完成数、未完成数和完成率。
2. **今日四项行动**：日期、四个推荐位、推荐理由、任务状态和操作按钮。
3. **任务面板**：搜索、主线/支线筛选、全部/进行中/已完成筛选、任务列表和新任务入口。
4. **任务卡片**：完成勾选、类型、优先级、标题、描述、进度条、章节标签、状态和子任务展开区。
5. **任务编辑器**：任务名称、描述、章节、类型、优先级、截止日期、进度，以及拆解预览。

## 交互不变量

- 每个任务卡片使用稳定 `data-task-id`。
- 勾选任务会更新任务状态和进度，并刷新面板统计。
- 完成任务后再次打开页面，状态仍然保持。
- 删除任务必须有浏览器确认；不允许一键清空全部状态。
- 复杂任务的拆解预览必须先展示，用户点击确认后才写入子任务。
- 每个自然日只保留一组四位推荐；刷新页面不重复追加。
- 推荐引用不存在的任务时，页面要显示异常并不执行完成操作。
- 输入框和按钮在手机宽度下仍可点击，长标题和描述不能破坏布局。

## 本地保存

默认使用：

```text
localStorage key: gamelife-skill:state:v1
```

写入前更新 `updated_at`。读取到无法解析或不兼容的状态时，保留原始值并回退到示例状态，同时向用户显示“已使用示例数据”提示；不能静默丢弃可恢复的状态。

`0.1` 不提供对话导出/上传流程，也不要求 HTML 连接后端。可交互状态的保存仅限浏览器本地状态，Agent 的正式状态更新遵循 `data-schema.md`。

## 响应式策略

- 桌面端：内容最大宽度约 1120px，任务区域和今日推荐可使用双列布局。
- 移动端：单列布局，卡片垂直堆叠，表单字段全宽，底部操作区不遮挡内容。
- 优先保证文字可读、按钮可操作、任务状态清晰，再追求装饰细节一致。
- 不为移动端另建一套数据模型。

## Agent 与 HTML 的边界

Agent 负责从对话中分析意图、识别事实、拆解任务和生成推荐理由；HTML 负责用户点击、编辑、确认和本地呈现。HTML 内的拆解按钮提供无网络的轻量兜底预览，不代表已经调用了语言模型。

当 Agent 生成新状态或修改状态时，应使用同一数据契约重新生成/更新 HTML，并向用户说明产物位置。不能声称已经同步到浏览器当前 tab，除非运行环境确实验证了该操作。
